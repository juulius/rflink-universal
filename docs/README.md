## How we write documentation

1. Start with **what you will do**, **why it matters** and **what you should see**. Put detailed technical explanations in an Advanced section.
2. Use plain English; define abbreviations the first time they appear.
3. Write short, numbered steps and include real screenshots only after confirming they match the current interface.
4. Distinguish **planned**, **implemented**, **host-tested**, **built with official ESP-IDF** and **hardware-tested**.
5. Document **v0.7 only**. Do not copy obsolete v0.6 ESPHome YAML, old web UI menus or installation steps.
6. Keep interface and firmware version names consistent, and update affected guides when functionality changes.
7. Explain errors and recovery steps clearly. Do not claim a feature is available before it works.

A tested step-by-step firmware installation guide will be added after the first official build and hardware validation.
