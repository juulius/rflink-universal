Wi-Fi shows the same captured ESP-IDF application logs as USB on supported firmware, alongside structured events and the last 12 saved restarts. The console ring is bounded and volatile; boot ROM messages and failures before application startup cannot be replayed via Wi-Fi. USB is required for those failures: connect the monitor, then press the physical reset button to capture early boot text. If the port disappears, the read-only monitor retries for up to 120 seconds. Review exported logs for private information before sharing.

Defaults for new RFLinks

Copied only when creating a new RFLink. They do not update an installed device. All settings stay local to Home Assistant.

Configure GPIO pinout, status LED and SPI speed

The Builder checks duplicate and reserved GPIO pins, including the WS2812 status LED (GPIO48 by default). A different LED pin or SPI/radio pinout changes the board profile hash and may require USB installation. LED brightness and on/off are configured on the RFLink itself.

Default Wi-Fi & local development credentials

The new-device wizard uses the default Wi-Fi settings but generates a unique OTA password for each RFLink. The default OTA key above is for legacy or local development builds.

Container RAM includes filesystem cache and child processes such as ESP-IDF. The working-set estimate excludes inactive file cache, but is not an exact measure of reserved RAM. The Python value includes only the webserver. An idle cleanup attempts to return unused Python allocator pages after builds or network activity; it may not reduce RSS. Anonymous RSS and thread count help investigate lingering HTTP connections. Percentages use a labelled host RAM or container memory limit and may not match Home Assistant's own chart. Samples are taken every five seconds; brief peaks can be missed.

Packages by RFLink and safety details

No storage report yet.

Only a firmware that has booted and passed OTA health validation replaces a verified local recovery copy. During a pending update, an additional package is kept. USB writes are not boot verification, so before a verified OTA, manual cleanup keeps two recent packages and should be used with care. The last selected build and any running installation remain protected.

The compiler toolchain and source files are not removed. The retained package contains an OTA image, USB files, a ZIP and potentially private Wi-Fi/OTA provisioning data. Compiled packages are excluded from Home Assistant backups and can be rebuilt from saved settings and published source versions.
